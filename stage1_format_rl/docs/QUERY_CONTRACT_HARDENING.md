本文保留当时严格策略的历史验证。2026-10-08 起，默认 `validation_policy: rods` 将额外项目规则改为诊断，提示词也不再强制本文的模板和 LC 位置阈值；`strict` 模式仍可复现这些规则。当前政策见 [RODS_VALIDATION_POLICY.md](RODS_VALIDATION_POLICY.md)。历史候选和原 verdict 不改写。

原始复审、反例和真实执行证据保留在 `/mnt/data/toolweave_four_category_smoke/query_review_20261007/`。这次修订约束新任务的输入与验收，不修改冻结的 BFCL VM、MatchTIR 或训练奖励。

## 生成角色的变化

Planner 仍一次生成完整任务叙事和各轮函数框架，输入没有原学生 rollout 或拓扑 JSON。对于需发送或输出历史事实的文本，叙事规定未填值的精确格式及取值规则，例如 `File: {filename}; Lines: {lines}`。不得把初始快照中的事实提前填进模板作为用户已知答案。

Parameter Generator 按实际成功返回填写格式，保留大小写、标点、空格。四类 Query Generator 和逐轮 verifier 都得到本次新任务先前成功调用与真实 Observation，供逆向写出请求和审查依赖。这些历史字段不包含内部 pre/post 快照。Query 使用同一未填值模板和明确选择规则，不能把历史答案直接抄成新的用户输入。`grep` 搜索字符串在本轮请求中精确引用，包括尾随空格。

Coherence Rewrite、Missing Parameter Transformer、最终 verifier 和 Judge 使用一致的项目补充规则。润色或澄清后必须保留模板、选择规则和搜索文本。已有官方提示词主体仍在使用，但附加了项目提示，不能宣称整套提示词未修改。

真实测试还发现逐轮 verifier 把“对返回的用户名字排序、展示两个选项”误认为必须增加工具调用。新增 `response_presentation.txt` 在逐轮、最终 verifier 与 Judge 中共享：GT 记录工具调用，助手可以根据实际可见结果做确定性的答案整理。发送、写入、删除等真实操作仍必须有 GT；不能借此引入隐藏事实、补给缺失的用户选择或接受任意消息措辞。该规则不证明未来 Actor 一定会正确整理答案。

## 新的确定性 gate

`query_contract_gate` 插入最终模型语义检查之前，Query Refine 后重复检查，不能由 Judge 的接受覆盖。

- 精确文本参数目前审计 `send_message.message` 和 `echo.content`；不把 ID、路径或所有工具字符串参数一概当成摘要。
- 文本必须是用户明确提供的新字面量，或匹配明确引入、未填值的精确模板。检查已执行文件读取后粘贴完整历史答案的绕过。
- 每个槽值绑定到成功执行的 Actor 可见返回，记录 turn/call、返回路径、字符位置与转换。支持直接值、可见数组长度、已支持的函数声明选择和末尾固定词数。字符/行/词计数槽限定对应 `wc` 单位的 `result.count`；匹配行数槽限定 `grep` 的 `result.matching_lines.length`。不能用目录长度补搜索计数，也不能把字符数当行数。失败调用、缺失轮和内部快照不能提供依据。
- 每个正常 `grep` 的实际模式必须在该轮 Query 中精确引用。最终模型检查还判断引用的模式是否确实为用户要求的搜索条件。
- LC 后轮精确文本必须使用同一个早期大型标量文本中的两个不同值。该文本至少 2048 字符，两个值的覆盖跨度至少 50%，其中一个值落在最后 20%。位置按真实标量文本计量；此前的 JSON 暴露门槛仍单独存在。全部阈值是项目政策。

新增检查不是完整的跨轮因果恢复算法。一般槽的语义选择、多个同值来源的区别、工具替代方案、自然语言目的及要求是否明确仍有模型审查的限制。当前 LC 策略针对大型标量文本，不能据此宣称涵盖所有大型结构化 JSON。精确模板也不证明整条调用轨迹唯一。
